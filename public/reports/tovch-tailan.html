Мэдээллийн сангийн бүтэц

Хоёр тусдаа сан: бизнес (65 хүснэгт, PostGIS) + хэрэглэгч/эрх, хүний нөөц (19 хүснэгт) · 14 migration (бизнес 13 + хэрэглэгч 1)

Хүснэгтүүд — сэдвээр (нийт 84)
  • Газарзүйн багана — талбарын хил, давхцлыг сан дотор автоматаар тооцно
  • 3 зэрэгцээ үнэлгээ — талбар бүрд илгээх→батлах хяналттай урсгал
  • Түүхжүүлэлт — өөрчлөлт бүр түүхийн хүснэгтэд үлддэг · SHA-256 — Excel давхардлын хамгаалалт
«Хүснэгт» гэдэг нь нэг төрлийн мэдээллийг эмх цэгцтэй хадгалах Excel-ийн хуудастай төстэй бүтэц. «Migration» нь сангийн бүтцийн өөрчлөлт бүрийг дугаарлан хадгалсан алхам (бизнес санд 13, хэрэглэгчийн санд 1; өмнөх алхмууд нэгтгэсэн baseline-д шингэсэн) — шинэ орчинд сан ямар ч үед мөр дараалан ижил бүтэцтэй босдог гэсэн үг.
Газарзүйн багана — талбарын давхцал, чөлөөлөх хэсгийн хэмжээг гараар хэмжихгүй: сан өөрөө координатаас нь томьёогоор бодно, хүний алдаа арилна. 3 зэрэгцээ үнэлгээ — нэг талбарыг гурван байгууллага бие биенээсээ хараат бусаар үнэлж, санхүү аль нэгийг нь сонгодог тул үнэлгээ бодитой, харьцуулагдахуйц болно. Түүхжүүлэлт — «өчигдөр ямар утгатай байсан, хэн, хэзээ өөрчилсөн» гэдгийг хэзээд эргүүлж харах боломжтой. SHA-256 дедупликаци — файл бүр давтагдашгүй «хурууны хээ»-тэй тул нэг Excel-ийг андуураад хоёр дахин оруулбал систем таньж зогсооно.
5

API интерфейс — 281 endpoint

Endpoint-ууд — бүлгээр
  • SSE стрийм — Excel тайлан явцын мэдээлэлтэй татагдана
  • GeoServer прокси — газрын зургийн сервер гадагш ил гардаггүй
  • Rate limit — нэвтрэлтийн оролдлогыг минутад 30-аар хязгаарлана
SSE стрийм гэж юу вэ? Том Excel тайлан бэлдэхэд минут дамжин үргэлжилж болно. Ердийн аргаар бол хэрэглэгч дэлгэц «гацсан» мэт чимээгүй хүлээдэг. SSE-ээр сервер бэлдэж байх явцаа («350/2000 мөр...») хөтөч рүү цувуулж мэдэгддэг тул явцын хувь бодитоор харагдаж, холболт тасрахгүй. Прокси — газрын зургийн серверт гаднаас шууд хандах боломжгүй, бүх хүсэлт нэвтрэлтээ шалгуулж үндсэн системээр дамждаг тул халдлагад өртөх «хаалга» цөөрнө. Rate limit — нэг хаягаас минутад 30-аас олон нэвтрэх оролдлого хийвэл түр хориглодог тул нууц үг таах (brute-force) халдлага ажиллахгүй.
Гадны үнэлгээний байгууллагууд ерөнхий сувгуудыг огт ашиглахгүй — тэдэнд зориулсан тусдаа 45 сувагтай портал (/prof) байдаг тул дотоод мэдээлэлд халдах боломжгүй.

12 цаг хүчинтэй токен (JWT) — нэвтэрсний дараа олгогдох токен нь богино настай тул хулгайд алдагдсан ч ашиглагдах хугацаа нь маш бага; систем ард нь өөрөө шинэчилж байдаг тул хэрэглэгч мэдэрдэггүй. bcrypt хэшлэлт — нууц үг сан дотор ил бишээр хадгалагддаг тул өгөгдөл алдагдсан ч нууц үг сэргээгдэхгүй. 3Эрхийн тохиргоо2.2.3✔ ХийгдсэнГУС-ийн чиг үүргийн ангиллыг системийн 6 роль, зөвшөөрлийн (resource:action) бүтэцтэй харгалзуулах тохиргоо
4Ажилтны бүртгэл2.3.1✔ ХийгдсэнТөрийн албан хаагчийн бүртгэлээс нэр, албан тушаал, хэлтэс/газрын мэдээлэл — хариуцагч оноох жагсаалтын эх сурвалж
5Ажилтны лавлахууд2.3.2✔ ХийгдсэнАлбан тушаал, нэгж/хэлтсийн лавлах — гараар бүртгэхийн оронд ГУС-аас синхрончлох
6Хуулийн этгээдийн бүртгэл2.3.3✔ ХийгдсэнХуулийн этгээдийн улсын бүртгэлээс регистр, нэр, хаяг — эзэмшигч, төлөөлөгчийн мэдээллийг баталгаажуулах
7Үнэлгээний байгууллагын бүртгэл, тохиргоо2.3.4✔ ХийгдсэнТусгай зөвшөөрөлтэй үнэлгээний байгууллагын жагсаалт, лицензийн хүчинтэй хугацаа — системд оноох байгууллагын эх сурвалж

8Гэр хорооллыг орон сууцжуулах газар чөлөөлөлт2.2.1.1✔ ХийгдсэнЖилийн ГЗБ төлөвлөгөөний зөвшилцсөн давхаргаас тухайн ангиллын чөлөөлөлтийн хил, талбай, байршлыг татаж шинэ чөлөөлөлт автоматаар үүсгэх
9Авто зам, инженерийн шугам сүлжээний газар чөлөөлөлт2.2.1.2✔ ХийгдсэнМөн давхаргаас авто зам, шугам сүлжээний ангиллын хил, трассын мэдээллийг татах
10Нийгмийн дэд бүтцийн газар чөлөөлөлт2.2.1.3✔ ХийгдсэнМөн давхаргаас сургууль, цэцэрлэг, эмнэлэг зэрэг нийгмийн дэд бүтцийн ангиллын хилийг татах
В. ГУС-ийн бүрэлдэхүүн системүүдийн холболт (5)
11Газар зохион байгуулалт, хот төлөвлөлтийн цахим систем2.3.1✔ ХийгдсэнТөлөвлөгөөний хил, бүсчлэл, хориглолт-хязгаарлалтын мэдээлэл — талбарын өөрчлөлтийг ЕТ-ийн бүсчлэлтэй хянахад ашиглана
12Газрын кадастрын систем2.3.2✔ ХийгдсэнНэгж талбарын хил, эзэмшигч, эрхийн төрөл, гэрчилгээ, гэрээний дугаар — «Мэдээлэл дуудах» синхрончлолын үндсэн эх сурвалж
13Газрын үнэлгээний систем2.3.3✔ ХийгдсэнҮнэлгээний бүс, зэрэглэл, газрын суурь үнэ, дуудлагын итгэлцүүр — олговрын тооцооллын суурь утгууд
14Хот байгуулалтын кадастрын систем2.3.4✔ ХийгдсэнБарилга байгууламжийн бүртгэл, хил, зориулалт — байгууламжийн үнэлгээг баталгаажуулах лавлагаа
15Газрын мониторингийн систем2.3.5✔ ХийгдсэнГазрын төлөв байдал, ашиглалтын хяналтын дүн — талбарын хяналтын картын мэдээлэл
Г. Кадастрын давхцал, зөрчлийн давхарга (3)
16Зөрчилтэй талбарын давхарга үүсгэх2.4.1.1✔ ХийгдсэнКадастрын одоогийн зургийг системийн чөлөөлөлтийн хилтэй харьцуулж, өөрчлөлт ороогүй/зөрчилтэй талбаруудыг тусдаа давхарга болгон зурагт харуулах
17Зөрчлийн мэдээллийг системд холбох2.4.1.2✔ ХийгдсэнИлэрсэн зөрчил бүрийг тухайн нэгж талбарын мэдээлэлтэйдэлгэрэнгүй хэсэгт харуулах холбож, дэлгэрэнгүйд нь харуулах
18Кадастрын давхцал шалгах хөгжүүлэлт2.9.1✔ ХийгдсэнКадастрын API-аас талбарын хил татаж, системийн PostGIS тооцоололтой тулган давхцлыг автоматаар шалгах
Д. Эрх, захирамжийн урсгал (2)
19Чиг үүргийн дагуу хэрэглэгчийн эрх тохируулах2.4.3.1✔ ХийгдсэнГУС-ийн чиг үүргийн бүтцээс хэрэглэгч бүрийн ажлын хүрээг татаж, системийн роль/зөвшөөрөлд автоматаар буулгах
20Захирамжийн төсөл бэлтгэх2.4.4.3✔ ХийгдсэнСистемийн талбар, эзэмшигч, батлагдсан олговрын дүнг захирамжийн төслийн загварт автоматаар бөглөж, ГУС-ийн захирамжийн бүртгэлтэй уялдуулах

21УБЕГ — үл хөдлөхийн бүртгэл солилцох2.8.1✔ ХийгдсэнХУР (XYP) гарцаар /xyp/ownership/citizen/parcel дуудаж УБЕГ-ийн газар өмчлөлийн бүртгэл (өмчлөгч, эрхийн төрөл, талбай, бүртгэлийн огноо) татагдаж parcel_ownership-д хадгалагдана; «Эзэмшигч» табд огноогоор бүлэглэн, «Шинэчлэх» товчтой харагдана
22Татварын ерөнхий газар — өр, төлөлт шалгах2.8.2✔ ХийгдсэнГУС-ийн төлбөр, нэхэмжлэлийн мэдээлэл татах хэсгээр хийгдсэн — татвар, төлбөр төлөгдмөгц ГУС дээр автоматаар шинэчлэгдэж, «Мэдээлэл дуудах»-аар шинэ мэдээ татагдан «Барьцаа, төлбөр» табд харагдана
23ШШГЕГ — шүүхийн маргаан шалгах2.8.3✔ ХийгдсэнГУС-ийн шүүхийн шийдвэр, барьцаа, эрхийн түтгэлзүүлэлт татах хэсгээр хийгдсэн — шүүхийн шийдвэр ГУС дээр шинэчлэгдэмгц татагдаж «Барьцаа, төлбөр» табд маргаан, түтгэлзүүлэлт болон харагдана
24Чөлөөлсөн газрын үнийн мэдээний сан2.8.4✔ ХийгдсэнГадаад системд зориулсан GET /api/v1/external/compensations — API key-тэй, нэгж талбарын дугаар / төлөвлөгөөний нэгж талбар / төлөвлөгөөний дугаараар шүүнэ. Зөвхөн үндсэн (тайлангийн) үнэлгээний дүн + төлөвийн тоолол буцна

26Давхаргыг динамикаар үүсгэх, тохируулах2.8.6✔ ХийгдсэнГУС-ийн давхаргын каталогоос сонгосон давхаргыг системийн газрын зурагт кодгүйгээр нэмж/хасах тохиргоо
Ж. Бусад (1)
27Бусад системүүдэд өгөгдөл холбож харуулах2.9.2✔ ХийгдсэнНээлттэй GIS давхарга land:v_parcel_public — эрх шалгахгүй WMS/WFS гарцаар чөлөөлөлтөд өртсөн бүх нэгж талбар, явцын нэр ба өнгөтэйгээр, дүүргээр шүүж дуудна. Мөн олговрын REST API (№24) гадаад системд өгөгдөл гаргана
ГУС-ийн 21 холболт «холбох + туршиж баталгаажуулах» мөчлөгөөр аль хэдийн ашиглалтад орсон — кадастр, ГЗБ/хот төлөвлөлт, газрын үнэлгээ, хот байгуулалтын кадастр, мониторингийн дэд системээс нэгж талбарын мэдээлэл 19 дуудлагаар татагдаж байна. Түүн дээр ХУР (XYP) гарцаар УБЕГ-ийн өмчлөл, E-Mongolia-ийн мэдэгдэл нэмэгдэж, системээс гадагш хоёр гарц нээгдлээ: API key-тэй олговрын REST API ба эрх шалгахгүй нээлттэй GIS давхарга (land:v_parcel_public). Иймд Е, Ж бүлгийн ажил бүрэн хаагдаж, 27/27 холболт ашиглалтад орсон. 12.2-т хүлээгдэж буй албан бичгийн цахим хүргүүлэлт (2.4.2.3)-ын хувьд системийн тал бүрэн бэлэн — баримтын DOCX/PDF загвар, илгээлтийн түүхийн бүртгэл, имэйл/E-Mongolia гарц бэлэн бөгөөд батлагдсан албан бичгийн маягт гармагц ижил богино мөчлөгөөр хаагдана.
